## 1. 五分钟跑起来

```bash
npm install
npm run build     # 改动代码后需要重新构建
npm start         # 默认 http://localhost:3000，端口用环境变量 PORT 指定
```

### ⚠️ 必读：开发模式在当前环境不可用

**`npm run dev` 在这台机器上无法正常挂载客户端**：Next.js 开发模式的热更新 WebSocket
（`ws://host/_next/hmr`）握手失败（`net::ERR_INVALID_HTTP_RESPONSE`），
导致 React 无法完成 hydration——页面能打开、但所有点击都没有反应。

已用一个只含 `useState` + `onClick` 的空页面验证过：**同样点不动**。
所以这是运行环境问题，与业务代码无关；`npm run build` + `npm start` 的正式版本完全正常。

**结论：本地查看请用 build + start。** 换一台网络环境干净、或能正常建立本地 WebSocket 的机器，
`npm run dev` 大概率可以直接用。若必须用 dev 模式，排查方向：本地代理/安全软件拦截
`/_next/hmr` 的 WebSocket 升级请求。

## 4. 数据模型（`lib/types.ts`）

```ts
type FeedbackType = '非常符合' | '部分符合' | '没有印象' | '完全不符合';

interface BirthInfo {
  name?: string;
  gender: '男' | '女' | '其他';
  birthDate: string;   // 'YYYY-MM-DD'
  birthTime: string;   // 例如 '午时 11:00-13:00'，也允许 '不确定'
  birthPlace: string;  // 自由文本
}

type DimensionKey = 'overall' | 'career' | 'wealth' | 'marriage' | 'parents' | 'health';
type Trend = '上升' | '下降' | '震荡' | '转折';
type ActionTip = '推进' | '准备' | '保守' | '重点处理';
type Consistency = '一致' | '单信号' | '冲突';

interface LifeLinePoint {
  age: number; year: number;
  overall: number; career: number; wealth: number;
  marriage: number; parents: number; health: number;  // 内部 5-97，页面只显示档位
  phase: string; trend: Trend;
}

interface YearCardData {
  year: number; age: number;
  daxian: string;          // '32-41 岁 · 夫妻宫大限'
  phase: string;           // '责任扩大期'
  trend: Trend;
  mainJudgment: string;    // 一句主判断（现实语言）
  events: { text: string; priority: number }[];  // 3-6 条，按主次
  ziweiSignal: string;     // 紫微信号
  baziSignal: string;      // 八字信号
  consistency: Consistency;
  actionTip: ActionTip;
}

interface FeedbackRecord { year; dimension; feedback: FeedbackType; updatedAt: number }
type FeedbackMap = Record<string, FeedbackRecord>;   // key: `${year}:${dimension}`

interface YearNote {                                   // ★ 产品核心资产
  year: number; dimension: DimensionKey;
  text: string;          // 用户亲笔写的"这一年实际发生了什么"
  skipped: boolean;      // 用户明确选"先不写"
  updatedAt: number;
}
type YearNoteMap = Record<string, YearNote>;
```

### 四个必须遵守的产品硬约束

1. **页面不得出现具体分数。** 内部 `number` 只用于决定曲线高低与四档标签
   （`levelOf()`：`≥72 高位 / ≥58 中上 / ≥42 中位 / 其余 低位`）。
   需求明确禁止"78 分"这类伪精确表达。
2. **曲线必须是连续的年龄轴。** 横轴年龄 / 公历年份一一对应，
   同一年在不同维度切换时横轴位置**不得变化**。
3. **命理依据默认折叠。** 主判断与可验证事件优先展示，依据放在 `<details>` 里。
4. **可验证事件必须能"想起来"**：具体、可核对，不写"会有贵人相助"这类无法证伪的话。

## 5. 数据流与存储

### 5.1 为什么用客户端组件

出生信息与反馈都存在 `localStorage`，服务端读不到。因此：

- `app/dashboard/page.tsx` 只做 metadata + 渲染 `<DashboardClient />`。
- `DashboardClient` 挂载后读一次本地数据；**没有出生信息就 `router.replace('/?need=birth')`**。
- 读取期间显示"正在读取你填写的出生信息…"（这是服务端预渲染的 HTML 内容）。
- `DashboardBody` 用 `key={birthDate + birthTime}` 挂载，换人填写时全部状态自动重置。

> 注意：`useEffect` 里同步 `setState` 会被 `react-hooks/set-state-in-effect` 报错，
> 现有代码在该处用了一行 `eslint-disable-next-line` 并附了原因。改动时请保留注释。

### 5.2 localStorage 合约（`lib/storage.ts`）

| key | 内容 | 写入时机 |
|---|---|---|
| `lifeline.birth` | `BirthInfo` | 首页表单提交 |
| `lifeline.feedback` | `FeedbackMap` | 点四档反馈按钮 |
| `lifeline.notes` | `YearNoteMap` | 点「存进我的核对档案」或「这一年先不写」 |
| `lifeline.draft` | `string` | 追问输入框每次变化（自动保留草稿） |

所有 `load*` 都做了 try/catch 与结构校验，损坏数据返回空值而不是抛错。
`clearFeedback()` 会同时清掉 `feedback` 与 `notes`（顶栏「重新填写」会调用它 + `clearBirth()`）。

**迁移到云端时**：只需替换 `lib/storage.ts` 的实现（改成读写接口）。
其余组件全部通过这 10 个函数访问数据（4 组 × load/save，外加 2 个 clear），不需要改动 UI。

### 5.3 仪表盘状态机（`components/dashboard-client.tsx`）

```
birth            BirthInfo（由外层传入，稳定不变）
dimension        DimensionKey        当前维度
selectedYear     number | null       当前年份
feedbackMap      FeedbackMap         反馈（初始化时读本地）
notes            YearNoteMap         核对档案
panelOpen        boolean             追问面板开关
suggestion       string | undefined  自动带出的追问问题
draft            string              追问草稿
```

派生数据（`useMemo` / 直接计算）：

- `points` = `buildLifeLine(birth)`：1-88 岁完整曲线（88 个点）
- `stage` = `buildStageCard(points, birth)`：当前阶段卡
- `index` / `point`：由 `selectedYear` 定位到曲线上的点
- `reviewedYears`：已核对年份去重集合
- `nextYear` = `nextUnreviewedYear(stage.year - 1, MIN_AGE, reviewedYears)`
- `reviewedRows`：按年份归并的核对记录（给 `ReviewedYears`）
- `archiveEntries`：有原文的条目按年份排序（给 `LifeArchive`）

### 5.4 四条关键行为（改动时别破坏）

| 行为 | 实现位置 | 规则 |
|---|---|---|
| 打反馈后自动追问 | `handleFeedback` | **仅在该年该维度第一次给反馈时**弹出面板并带出 `suggestion`；改档位不重复弹 |
| 追问问题随档位变化 | `lib/notes.ts` → `buildSuggestion` | 四种档位各有两套话术，按 `(year + feedback.length) % 2` 稳定选择；档位与趋势共同决定用词 |
| 继续核对从去年开始 | `nextUnreviewedYear(stage.year - 1, ...)` | 今年还没过完，不下结论。年度卡片把今年单独标为「当前位置」 |
| 跳转后滚动到卡片 | `yearCardRef` + `lastScrolledYear` | 只在年份**真正变化**时滚动，首屏不滚；容器有 `scroll-mt-20` 避开吸顶栏 |

## 6. 模拟数据引擎（`lib/mock-data.ts`）

**这是接手后第一个要动、也是唯一需要整体替换的文件。**

### 6.1 三条设计原则

1. **确定性**：同一个人（同一份 `BirthInfo`）每次打开、每次刷新，曲线与文案完全一致。
   实现方式是 FNV-1a 哈希 + 稳定伪随机（`hash/rng/rint/pickN/pickOne`），
   种子由 `birthDate|birthTime|gender` 与年份派生。
   **禁止**引入 `Math.random()` 或 `Date.now()` 参与内容生成。
2. **曲线不加逐年噪声**：`scoreAt()` 只由「长期形状 `SHAPE` + 双正弦个人节律 `WAVE` + 个人整体偏移」
   组成。早期版本加了逐点随机抖动，曲线长满毛刺、不像人生轨迹，已移除。
3. **文案按人生阶段分池**：判断文案分 `early(1-18) / young(19-32) / adult(33+)` 三套
   （`JUDGMENT_POOL_EARLY/YOUNG/ADULT`），事件池按"维度 × 人生阶段带"分（`EVENT_POOL`）。
   这是为了避免童年年份出现"职业决定影响后面十年"这类不合年龄的话——
   **新增文案时必须遵守这个分层**。

### 6.2 对外 API

```ts
CURRENT_YEAR: number                       // new Date().getFullYear()
MIN_AGE = 1; MAX_AGE = 88                  // 曲线覆盖范围
BANDS: Band[]                              // 10 个人生阶段带
bandOf(age) / phaseOf(age)                 // 年龄 → 阶段带 / 阶段名
daxianOf(age): Daxian                      // 年龄 → 大限（2 岁起运，10 年一换，宫位顺序见 PALACES）
buildLifeLine(birth): LifeLinePoint[]      // 生成 88 个点
buildStageCard(points, birth): StageCard   // 当前阶段卡
buildYearCard(points, index, dimension, birth): YearCardData
levelOf(value): Level                      // 数值 → 高位/中上/中位/低位
nextUnreviewedYear(currentYear, minAge, reviewedYears): number | undefined
```

### 6.3 大限与信号规则（当前为演示规则，接真排盘时会整体替换）

- **大限**：2 岁起运，每 10 年一换；宫位顺序硬编码在 `PALACES`
  （父母宫 → 命宫 → 兄弟宫 → 夫妻宫 → 子女宫 → … 与常见安宫顺序相近）。
  **注意**：真实紫微大限的起运岁数与顺逆排序需按性别与生年干支计算，当前是简化版。
- **趋势判定** `trendOf(prev, cur, next)`：相邻年差值 > 2.5 视为方向变化；
  方向不一致 → `震荡`；平稳但有 ≥2 分落差的主峰/主谷 → `转折`。
- **一致性判定**：紫微与八字各自带 `tone`（`good` / `mixed` / `bad`）。
  两者相同 → `一致`；任一为 `mixed` → `单信号`；一好一坏 → `冲突`。
  **文案与判定是绑定的**：改文案必须同步改 `tone`，否则会出现"紫微说大吉、八字说大凶，
  却标注为一致"的矛盾。

### 6.4 各维度曲线的形状设定

`SHAPE` 定义每个维度的关键年龄锚点值（0-100），锚点之间用 `smoothstep` 平滑插值；
`WAVE` 定义每人不同的节律（主周期 + 次周期双正弦）。当前设定：

| 维度 | 走势意图 |
|---|---|
| overall | 儿童期低、40 岁前后见顶、之后缓降 |
| career | 25 岁起爬升、48 岁前后见顶、60 岁后明显回落 |
| wealth | 33 岁后稳步积累、50 岁见顶、65 岁后回落 |
| marriage | 20 岁后快速上升、40 岁前后小低谷、晚年回升 |
| parents | 幼年高位（被照顾）、中年低位（父母老去）、晚年下行 |
| health | 随年龄缓慢下行，50 岁前后最紧张 |

调整这些数值即可改变产品"叙事"，**改完必须跑 §10 的 `smoke.ts` 复核**。

## 7. 关键模块说明

### 7.1 `chen-teacher-panel.tsx`（追问面板）

- Props 见文件顶部 `interface Props`，共 12 个；面板**不是**受控弹窗，
  `open === false` 时直接 `return null`。
- 面板内三种交互：发消息（占位回答）、保存核对档案、跳过（写 `skipped=true`）。
- `savedNote` 通过 `useState(savedNote ?? '')` 初始化一次；
  外层用 `key={`${year}:${dimension}`}` 强制换年时重新挂载，避免残留上一年内容。
  **改动时不要去掉这个 key。**
- `placeholderAnswer(year, feedback)` 是**接 AI 的唯一替换点**（见 §8.2）。

### 7.2 `life-archive.tsx` / `reviewed-years.tsx`

- `LifeArchive`：`entries` 为空时整块不渲染（外层 `dashboard-client` 已判断）；
  条目 ≥3 条时默认展开。`buildPlainText()` 生成"复制全文"的文本格式，
  改格式就改这一个函数。
- `ReviewedYears`：按年份分组，每年固定渲染 6 个维度槽位：
  已核对 → 彩色按钮（`非常符合/部分符合` 绿、`没有印象` 灰、`完全不符合` 红；带 ✎ 表示有原文）；
  未核对 → 虚线"待核对"。点彩色按钮回调 `onPick(year, dimension)`。

### 7.3 `life-curve.tsx`（纯 SVG 曲线）

为什么不用图表库：需要「过去实线 + 未来虚线」「当前年龄醒目竖线」「88 个可点击年份节点
且按位置分配命中区域」「横轴双行标签（年龄 + 年份）」这些非常规组合，
手写 SVG 比配置图表库更短、更可控，也不引入额外依赖。

几何参数（改布局看这里）：

```ts
const W = 1136, H = 420;
const PAD = { left: 56, right: 36, top: 40, bottom: 76 };
// 数值 5-97 映射到纵向；四档参考线在 72 / 58 / 42 / 22
```

- 平滑曲线：Catmull-Rom 转三次贝塞尔（`smoothPath`），并把控制点限制在画布内防溢出。
- 命中区域：每个年份一个 `r = max(3.4, 绘图宽/年数/2.1)` 的透明圆，
  带 `role="button"` 与键盘 `Enter/Space` 支持；`.node` 默认透明、hover 时显现（见 `globals.css`）。
- 移动端：外层 `overflow-x-auto`，`useEffect` 里按比例把容器滚到「现在」居中。

### 7.4 样式与设计令牌（`app/globals.css`）

Tailwind v4 的 CSS-first 写法：`:root` 定义变量，`@theme inline` 映射成工具类，
然后就能用 `bg-surface` / `text-ink-2` / `border-line` / `bg-accent-soft` 等。

| 令牌 | 用途 |
|---|---|
| `paper` `surface` `line` `line-strong` | 底色 / 卡片 / 边框 |
| `ink` `ink-2` `ink-3` | 三级文字 |
| `accent` `accent-soft` | 主色（暖橙）与其浅底 |

**只做浅色主题**（没有 `dark:` 分支），SVG 内部颜色是字面量（`#a8531f` 等，定义在
`life-curve.tsx` 顶部常量里）。若要做深色模式，需要同时改这两处。

## 8. 如何接入真实能力（两个集成点）

### 8.1 接真实排盘（替换模拟数据）

页面层与数据层已经分离，**UI 不需要改**：

1. 新建 `lib/chart.ts`，导出与 §6.2 同名的函数。
2. 把 `dashboard-client.tsx` 里 `from '@/lib/mock-data'` 的导入改成 `'@/lib/chart'`。
3. 排盘计算（紫微安星、八字排盘）**建议放服务端**：新建 `app/api/chart/route.ts`，
   客户端 `POST { birth }` 拿到结果；`dashboard-client` 里把
   `const points = buildLifeLine(birth)` 换成异步获取 + `useState` 缓存。
   这样可以把排盘库（依赖体积大、常含农历/节气数据）排除出客户端包。
4. `YearCardData` 里 `ziweiSignal / baziSignal / consistency` 三个字段由真实信号生成；
   注意 §6.3 提到的 tone 与一致性绑定关系。

> 数据契约建议保持不变：**只要 `LifeLinePoint` 与 `YearCardData` 的字段不变，
> 9 个组件全部不用动。** 如果真实排盘需要额外字段（如星曜列表、十神），
> 请以可选字段追加，不要改现有字段语义。

### 8.2 接真实 AI（替换占位回答）

1. 新建 `app/api/ask/route.ts`：接收 `{ year, age, dimension, daxian, phase, trend,
   mainJudgment, events, feedback, note, history, question }`，
   在**服务端**拼 system prompt 并调用模型，`OPENAI_API_KEY` 之类的密钥只存在于服务端。
2. `chen-teacher-panel.tsx` 的 `send()` 里，把 `placeholderAnswer(...)` 换成
   `fetch('/api/ask', ...)`；建议用流式响应（`ReadableStream`）+ 逐字追加到 `messages`。
3. **上下文已经备齐**：面板顶部 `history` 是最近历史反馈、`savedNote` 是用户亲笔经历、
   `card` 是当年全部判断要素——这些就是 prompt 的素材，不需要再让用户重复描述背景，
   这正是产品主张的"带着年份和反馈去追问"。
4. 接完 AI 后建议删除 `placeholderAnswer` 里的"（示例回答…）"前缀。

### 8.3 数据持久化

替换 `lib/storage.ts` 的 10 个函数即可（`loadBirth`/`saveBirth`/`clearBirth`、
`loadFeedback`/`saveFeedback`/`clearFeedback`、`loadNotes`/`saveNote`、
`loadDraft`/`saveDraft`）。
建议提供一个"导出我的档案"接口（`LifeArchive` 的 `buildPlainText()` 已经是现成的文本格式），
因为 `lifeline.notes` 是用户不可再生的资产，浏览器清缓存就会丢。

## 11. 常见坑

1. **改文案忘了改 tone** → 出现"紫微凶、八字吉却标一致"。见 §6.3。
2. **给 `scoreAt` 加随机抖动** → 曲线立刻长毛刺。见 §6.1。刻意不加逐点噪声。
3. **去掉面板的 `key={year:dimension}`** → 换年时面板残留上一年的输入内容。
4. **在 `useEffect` 里直接 `setState`** → ESLint 新规则报错；本项目只在一处允许（附注释）。
5. **用 PowerShell 的 `Set-Content` 批量改这些文件** → 会按 UTF-8 重写并可能弄坏中文编码。
   请用编辑器的文本编辑功能（或 `edit`/`write` 类工具）。
6. **`next build` 报 `Cannot find module '../../../app/xxx/page.js'`** →
   `.next/dev/types/validator.ts` 里残留了已删除页面的类型。删掉整个 `.next` 重新构建。
7. **页面点击没反应** → 先确认是不是用了 `npm run dev`（见 §1），而不是业务代码问题。

## 13. 需要业务方确认的开放问题

1. **大限口径**：起运岁数与顺逆排法按哪一派？当前是简化的"2 岁起运、固定顺排"。
2. **"没有印象"的含义**：应视为"判断不准"还是"这一年太平淡"？当前文案按后者处理，
   并建议标记为"待验证"。这会直接影响反馈回流算法。
3. **反馈回流规则**：`非常符合 / 部分符合 / 没有印象 / 完全不符合` 如何影响后续年份的权重？
   目前只存不参与计算。
4. **核对档案的隐私边界**：用户亲笔经历是否上云、是否用于训练、能否一键删除，需要产品明确。
5. **是否要保留"我核对过的年份"中的"待核对"槽位**：它给用户方向感，
   但也可能造成"还有 30 年没做完"的压力，需真实用户验证。
